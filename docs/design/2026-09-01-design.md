# Claude Limit Buster — design

**Date:** 2026-09-01
**Status:** Approved, pre-implementation
**Upstream:** `BarPopko.claude-timeout-resume` v0.3.0 (MIT)

## Problem

Claude Code sessions stop on usage limits and transient server errors. Recovery
is manual: notice it stopped, wait out the reset, restart, retype the lost
prompt. The upstream extension automates this but does so by typing recovered
text into whichever VS Code terminal is focused, which is unsafe and — for
sessions running in the Claude Code panel — does not work at all.

## Goals

1. Detect usage limits, server errors, and input-needed states for **panel and
   terminal sessions alike**.
2. Resume the **correct** session unattended, without typing into a terminal.
3. Never escalate the user's autonomy level.
4. Bound token spend, because recovery competes with the quota it is recovering.

## Non-goals

- Resuming *inside* the Claude Code panel. No public API accepts a prompt
  (23 contributed commands, none qualify). Recovery lands in a terminal.
- Parsing transcripts for anything beyond detection. The format is explicitly
  internal and changes between versions.

## Findings that shape this design

Verified during audit and spike:

| # | Finding | Consequence |
|---|---|---|
| 1 | `sendText(prompt)` into an existing terminal executes as shell if Claude died | No writing to existing terminals, ever |
| 2 | `quoteForShell` leaves PowerShell `$(...)` live (verified: `$(1+41)` → `42`) | Never hand-quote; use argv |
| 3 | `soundCommand` runs arbitrary shell, undeclared, workspace-settable | Execution-adjacent settings are machine-scoped |
| 4 | `findLatestTranscript` falls back to newest jsonl anywhere | Target sessions by ID only |
| 5 | Broad transcript read surface | Keep parsing minimal |
| 6 | 6/10 ordinary user questions arm a timer; terminal path has no code guard | Fix admission control at the parser |

Spike results:

- Session ID **is** the transcript filename (verified).
- Headless `-p --resume` does **not** inherit permission mode (verified: an
  `acceptEdits` session resumed with `-p` was denied).
- Interactive terminal resume runs at the user's normal autonomy (verified:
  file created with no prompt).
- CLI resume of a panel session carries full context (verified).
- A cold resume of a 1.6MB session cost 288,574 cache-creation tokens.

## Architecture

```
transcriptWatcher ──> parsers ──> scheduler ──> resumer
                         │            │            │
                    sessionResolver   │         budget
                                   statusBar/alerts
```

### transcriptWatcher — carried

Tails `~/.claude/projects/**/*.jsonl`. Offset-tracked per file, baselined at
startup, consumes only through the last complete newline. `fs.watch` recursive
plus a poll backstop. Upstream code is sound; carried with tests added.

### parsers — engine carried, admission control rewritten

Carried unchanged: the rule sets and time resolution (epoch, ISO, named
timezones, UTC offsets, compound durations), ANSI stripping, horizon rejection,
`429`-routes-to-limit-parser. Scored 56/63 against a corpus built from upstream's
own documented coverage.

Three changes:

1. **Move `looksLikeCode` inside `detectLimit`**, mirroring `detectOverload`
   which already guards internally. Upstream placed it in one caller, so
   `detectLimitInLines` — the terminal path — has no guard at all.
2. **Gate the limit path on `entry.type !== 'user'`**, mirroring the overload
   path's existing rule ("the user pasting an error must never kick off an
   automatic retry"). Same reasoning, never applied to limits.
3. **Populate two gate lists**: bare `your limit` and bare `socket hang up`.
   Both documented upstream, both rejected by a pre-gate before the working
   rule runs.

### sessionResolver — new

Detection knows which file the limit came from. `basename(file, '.jsonl')` is
the session ID (verified). No most-recent-file heuristic, no `--continue`
(which resumes "the most recent interactive session" and skips `-p`, SDK,
background, and `/loop` sessions).

`cwd` comes from the transcript entries.

### resumer — rewritten

Spawns a **fresh terminal** and runs:

```
claude --resume <session-id> "<prompt>"
```

Prompt as argv, never typed. No `--permission-mode` flag — interactive resume
runs at the user's normal autonomy, so the extension grants nothing.

Optional, off by default, machine-scoped: headless mode using
`claude -p --resume <id> --output-format json`, which returns structured
`permission_denials` and `usage`. Requires an explicit permission mode to do
tool work, which is why it is opt-in.

Never targets an existing terminal. No `activeTerminal` fallback.

### budget — new

Recovery consumes the quota it is recovering, and a usage-limit wait guarantees
a cold cache.

- **Pre-flight (both modes):** `transcriptBytes / 5.6 ≈ tokens` (calibrated from
  1,618,394 bytes → 288,574 tokens; needs more data points). Refuse to resume
  above `maxResumeTokens`; surface the estimate in the confirmation.
- **Post-flight (headless only):** read `usage` from result JSON, accumulate
  across an incident, hard-stop on cumulative tokens.

**Asymmetry, stated plainly:** the default interactive mode returns no JSON, so
post-flight accounting is unavailable there — enforcement is estimate-only. Real
usage *is* recorded in the transcript's assistant entries and could be read back,
but that expands the parsing surface this design is trying to shrink. Deferred;
see Open items.

Either way this replaces upstream's `overloadMaxAttempts: 6`, which counts
attempts with no idea what each costs.

### scheduler, statusBar, alerts — carried

Scheduler compares wall-clock every second rather than one long `setTimeout`,
so it survives sleep and restart. Carried as-is.

`sound.js` carried **without** `soundCommand`.

## Settings

All declared in `contributes.configuration`. Execution-adjacent settings are
`"scope": "machine"` so a workspace cannot set them.

| Setting | Default | Scope |
|---|---|---|
| `enabled` | `true` | window |
| `autoResume` | `true` | window |
| `resumeMode` | `interactive` | **machine** |
| `headlessPermissionMode` | `""` (none) | **machine** |
| `maxResumeTokens` | `150000` | window |

`maxResumeTokens` is measured against the **pre-flight estimate**, not actual
usage. `0` disables the check.
| `randomDelayMin/MaxMinutes` | `5` / `30` | window |

## Testing

- The 63-case parser corpus becomes the regression suite at commit 1.
- **Known gap:** every fixture is synthetic, written from upstream docs. No real
  captured limit entry exists yet. Capture and add on first real limit.
- `sessionResolver` and `budget` estimator get unit tests.
- `resumer` is tested by asserting the spawned argv, not by running Claude.

## Open items

- Whether the panel renders a CLI-advanced session on reload. Docs say the
  extension and CLI share conversation history; the listing layer is per-client.
  Verify during build.
- Calibrate the bytes-per-token estimate across more sessions.
- Whether to read real `usage` back from transcript assistant entries so the
  default interactive mode gets post-flight accounting too. Trades a wider
  parsing surface for real numbers instead of an estimate.
